# Hodler Doc Generator Bot

Telegram-бот на **Go** для автоматической генерации актов и договоров на сделки с виртуальными активами для юридических лиц.

## Что умеет

- **2 типа акта**: «Продаём ВА клиенту» и «Покупаем ВА у клиента»
- **Счёт-заявка**: отдельный документ на покупку клиентом (`template_invoice_buy`) — формируется до акта
- **Разбивка на транзакции**: одна сумма сделки дробится на части (тест + остаток) — каждая строкой в таблице, рубли считаются по курсу, «Итого» = общая сумма
- **База компаний**: добавить один раз — реквизиты подтянутся автоматически
- **Журнал сделок** 🗂: каждый сгенерированный акт сохраняется в БД; документы можно переслать в любой момент (хранятся в Telegram по file_id, диск не занимают)
- **Отчёт ФН** 📊: выгрузка XLSX за месяц в формате Приложений 4/о («Продажа») и 5/о («Покупка») с пересчётом в сомы по курсу RUB→KGS
- **Автономер по клиентам**: бот помнит последний номер акта и счёта для каждой компании и предлагает следующий
- **Подписанные акты** 📎: загрузка сканов/PDF в сделку, выгрузка ZIP-архивом по каждому клиенту
- **Шаблоны через бота** 📄: загрузка/замена .docx без захода на сервер, скан плейсхолдеров, резервные копии
- **Свои переменные** 🧩: создайте `{{CL_KEY}}` — бот спросит значение при добавлении каждой новой компании
- **Автодата / автокурс / КВВО**: подставляются автоматически, можно изменить
- **PDF**: автоматическая конвертация через LibreOffice (изолированные профили + очередь — не виснет при параллельной работе)
- **Автоочистка**: сгенерированные файлы удаляются после отправки в Telegram; фоновая чистка подбирает остальное
- **Многопользовательский режим**: доступ по `ADMIN_IDS`, SQLite в WAL-режиме, параллельная работа нескольких сотрудников
- **Откупки** 🔁: одна покупка USDT у поставщика закрывает несколько заявок клиентов; бот подсказывает сумму перевода с учётом комиссии банка и показывает, хватает ли USDT
- **Прибыль** 📈: ЧКД, налог, рефералы, чистая прибыль по каждой сделке; отчёт за день в формате «📊 Классика за ДД.ММ.ГГГГ» и XLSX за месяц (транзакции, прибыль, откупки)
- **Рефералы** 👥: закрепляются за клиентом, процент от (ЧКД − налог)
- **Уведомления руководителям** 🔔: новые сделки, откупки, правки («было → стало») и отмены в групповой чат
- **Переделка и отмена заявки**: версии сделки, отменённые не попадают в отчёты
- **Версионные миграции БД**: база Python-версии подхватывается как есть, с резервной копией перед миграцией
- **Редактирование**: любое поле можно изменить перед генерацией

## Быстрый старт (Docker — рекомендуется)

### 1. Клонировать / скопировать проект

```bash
git clone <repo> hodler-doc-bot
cd hodler-doc-bot
```

### 2. Создать `.env`

```bash
cp .env.example .env
nano .env
```

Заполнить `BOT_TOKEN` и `ADMIN_IDS`.

### 3. Положить готовые шаблоны

В папку `templates/` поместить заполненные плейсхолдерами `{{...}}` файлы:
- `template_buy.docx` — клиент покупает ВА у нас
- `template_sell.docx` — клиент продаёт ВА нам
- `template_invoice_buy.docx` — счёт-заявка на покупку клиентом

Шаблоны создаются вручную (см. список плейсхолдеров ниже).

### 4. Запустить

```bash
docker compose up -d --build
```

При первом запуске автоматически создастся БД с реквизитами оператора по умолчанию.
Если в `data/` уже лежит `hodler.db` от Python-версии — она будет мигрирована (см. ниже).

## Локальный запуск (без Docker)

### Требования
- Go 1.26+
- LibreOffice (`libreoffice` в PATH)

```bash
go build -o hodler-bot ./cmd/hodler-bot
./hodler-bot            # шаблоны должны лежать в templates/
```

Тесты: `go test ./...`

### Команды бинарника

| Команда | Что делает |
|---------|------------|
| `hodler-bot` | запуск бота (недостающие миграции применяются автоматически) |
| `hodler-bot migrate` | только применить миграции и выйти |
| `hodler-bot migrate -status` | показать, какие миграции применены |
| `hodler-bot backup data/copy.db` | консистентная копия БД (`VACUUM INTO`, безопасно в WAL) |
| `hodler-bot export [-no-env] [файл.tar.gz]` | полная копия для переноса: БД + шаблоны + `.env` |
| `hodler-bot import [-force] [-no-env] файл.tar.gz` | развернуть полную копию на новом сервере |
| `hodler-bot purge-deals [-yes]` | очистить журнал сделок (компании, реквизиты, рефералы, нумерация остаются; перед удалением — резервная копия) |

## Миграция базы данных

Схема БД хранится в версионных миграциях `internal/storage/migrations/` и
таблице `schema_migrations`. Каждая миграция применяется один раз, в транзакции.

| № | Миграция | Что делает |
|---|----------|------------|
| 0001 | `baseline_schema` | схема Python-версии (`CREATE TABLE IF NOT EXISTS` — существующие таблицы не трогаются) |
| 0002 | `companies_resident` | колонка `companies.resident`, если её нет (старые базы) |
| 0003 | `seed_operator_defaults` | реквизиты оператора по умолчанию и счётчик номеров (`INSERT OR IGNORE`: ваши значения не перезаписываются) |
| 0005 | `buybacks_profit_notifications` | откупки, поставщики, рефералы, статус/версия сделки, снимок налога/комиссии/реферала, чаты руководителей и уведомления; параметры `tax_percent`, `bank_fee_percent`, `report_title` |
| 0004 | `data_cleanup_and_indexes` | индекс `signed_docs(deal_id)`, нормализация NULL/пустых значений, восстановление `deal_date_iso` из `ДД.ММ.ГГГГ` — такие сделки снова попадают в отчёт ФН |

### Переход с Python-версии

1. Остановить старый бот: `docker compose down` (или `systemctl stop hodler-bot`).
2. Оставить `data/hodler.db` и `templates/` на месте — формат таблиц не меняется.
3. Обновить код и запустить: `docker compose up -d --build`.

При первом старте бот обнаружит базу без `schema_migrations`, сделает копию
`data/hodler.db.backup-ГГГГММДД-ЧЧММСС` и применит миграции. Все компании, сделки,
`file_id` документов, подписанные акты, счётчики номеров, свои переменные и КВВО
сохраняются. Проверить: `docker compose run --rm hodler-bot hodler-bot migrate -status`.

Откат: остановить бот и вернуть файл из резервной копии на место `data/hodler.db`
(Python-версия работает с мигрированной базой, лишние таблица и индекс ей не мешают).

Новая миграция = новый файл `NNNN_name.sql` + запись в `Migrations` (`internal/storage/migrate.go`);
уже выпущенные миграции не меняются.

## Откупки и прибыль

### Как считается

| Показатель | Формула |
|------------|---------|
| Объём | ₽ / курс клиента — USDT, отданные клиенту |
| ЧКД | ₽ / курс откупки − Объём − комиссия банка (0,05%) × Объём |
| Налог | 5% × ЧКД |
| Реферал | процент реферала × (ЧКД − налог) |
| Чистая прибыль | ЧКД − налог − реферал |

Налог, комиссия и название отчёта меняются в «⚙️ Реквизиты». В каждой сделке налог, комиссия,
реферал и его процент сохраняются на момент сделки — поздняя смена настроек историю не переписывает.

Прибыль считается по продажам USDT клиентам (акты «Продаём ВА клиенту»), у которых есть откупка.
Сделки без откупки — это USDT, выданные наперёд: в отчёте они идут строкой «⏳ Ожидают откупки» и в итоги не входят.

### Откупка

🔁 Откупки → ➕ Новая откупка: отметить заявки → поставщик → курс → сумма перевода.
Бот предложит максимальную сумму, при которой хватит на комиссию банка (и её же, округлённую до 10 000),
и покажет баланс: сколько USDT куплено против нужного клиентам (недостача — доплата из прибыли)
и сколько рублей останется на счёте. Сумма откупки на ЧКД не влияет — только на остатки USDT и ₽.

Сделку можно закрыть откупкой и из её карточки (новой или уже существующей). Откупку можно изменить
(курс, сумма, поставщик, дата), добавить/отвязать сделки, отменить.

### Уведомления руководителям

1. Добавьте бота в группу руководителей.
2. Напишите в группе `/bind` с аккаунта из `ADMIN_IDS` (`/unbind` — отключить).

В группу приходят новые сделки и откупки. При переделке, отмене, восстановлении сделки бот
**отвечает** на исходное уведомление («✏️ изменена: Сумма ₽: 1 000 000 → 1 050 000», «❌ отменена») —
правку сообщения в Telegram никто не замечает, а ответ приходит уведомлением. Само исходное
сообщение тоже обновляется (отменённое — зачёркивается), так что лента всегда актуальна.
В группе работают `/today` и `/report ДД.ММ.ГГГГ` — отчёт о прибыли за день.

### Очистка журнала

```bash
docker compose exec hodler-bot hodler-bot purge-deals        # показать, что будет удалено
docker compose exec hodler-bot hodler-bot purge-deals -yes   # удалить (с резервной копией)
```

## Перенос на другой сервер

`hodler-bot export` собирает **один архив** `hodler-export-ГГГГММДД-ЧЧММСС.tar.gz`:

| В архиве | Что это |
|----------|---------|
| `data/hodler.db` | консистентный снимок БД — можно снимать на работающем боте |
| `templates/` | шаблоны DOCX вместе с `templates/backups/` |
| `.env` | токен и настройки; в Docker файла внутри контейнера нет — собирается из переменных окружения |
| `manifest.json` | дата, сервер, версии миграций, sha256 каждого файла |

Не переносится только `data/output/` (временные файлы): документы и подписанные акты
живут в Telegram, в базе — их `file_id`, поэтому на новом сервере всё доступно.

> ⚠️ В архиве `BOT_TOKEN`. Архив создаётся с правами `600`; передавайте его только по `scp`/`ssh`
> и удалите после переноса. Без секретов: `export -no-env`.

### Docker

На старом сервере (бот может работать):

```bash
docker compose exec hodler-bot hodler-bot export data/hodler-export.tar.gz
```

Архив окажется в `./data/` на хосте. Передать на новый сервер:

```bash
scp data/hodler-export.tar.gz user@new-server:/tmp/
```

На новом сервере — код, затем распаковка архива прямо в каталог проекта
(раскладка архива совпадает с каталогом проекта):

```bash
git clone <repo> hodler-doc-bot && cd hodler-doc-bot
```

```bash
tar xzf /tmp/hodler-export.tar.gz && rm manifest.json
```

Остановить старый бот (`docker compose down` на старом сервере) — один токен
не может работать на двух серверах одновременно — и запустить новый:

```bash
docker compose up -d --build
```

### Без Docker

```bash
./hodler-bot export /tmp/hodler-export.tar.gz          # старый сервер
scp /tmp/hodler-export.tar.gz user@new-server:/tmp/
```

На новом сервере, в каталоге бота (рядом с бинарником):

```bash
./hodler-bot import /tmp/hodler-export.tar.gz
```

`import` проверяет контрольные суммы и пути, раскладывает БД, шаблоны и `.env`,
применяет недостающие миграции. Существующие БД и `.env` без `-force` не трогает;
с `-force` прежние файлы сохраняются как `*.before-import-ГГГГММДД-ЧЧММСС`.

## Переменные в документах

Шаблоны содержат плейсхолдеры вида `{{VARIABLE}}`:

### Сделка
| Плейсхолдер | Значение |
|-------------|----------|
| `{{DEAL_NUMBER}}` | Номер заявки |
| `{{DEAL_DATE}}` | Дата заявки (ДД.ММ.ГГГГ) |
| `{{DEAL_DATE_FULL}}` | «ДД» месяц ГГГГ г. |
| `{{EXECUTION_DATE}}` | Дата исполнения |
| `{{OPERATION_TYPE}}` | Покупка / Продажа виртуальных активов |
| `{{KVVO}}` | Код вида валютной операции |
| `{{VA_TYPE}}` | USDT, BTC... |
| `{{NETWORK}}` | TRC-20, ERC-20... |
| `{{VA_TICKER}}` | USDT_TRC20... |
| `{{VA_AMOUNT}}` | Сумма ВА |
| `{{FIAT_AMOUNT}}` | Сумма RUB |
| `{{EXCHANGE_RATE}}` | Курс обмена |
| `{{TX_HASH}}` | Хэш транзакции |
| `{{COMMISSION_FIAT}}` | Комиссия в % (RUB) |
| `{{COMMISSION_VA}}` | Комиссия в % (ВА) |
| `{{CL_WALLET}}` | Кошелёк клиента |
| `{{OP_WALLET}}` | Кошелёк оператора |

### Оператор (`OP_*`)
`{{OP_FULL_NAME}}`, `{{OP_SHORT_NAME}}`, `{{OP_INN}}`, `{{OP_KPP}}`, `{{OP_ADDRESS}}`, `{{OP_ADDRESS_FULL}}`, `{{OP_LEGAL_ADDRESS}}`, `{{OP_LICENSE}}`, `{{OP_KIO}}`, `{{OP_INN_RF}}`, `{{OP_KPP_RF}}`, `{{OP_BANK_NAME}}`, `{{OP_BANK_ACCOUNT}}`, `{{OP_BANK_BIK}}`, `{{OP_DIRECTOR}}`

### Клиент (`CL_*`)
`{{CL_FULL_NAME}}`, `{{CL_SHORT_NAME}}`, `{{CL_INN}}`, `{{CL_KPP}}`, `{{CL_REG_NUMBER}}`, `{{CL_ADDRESS}}`, `{{CL_KIO}}`, `{{CL_INN_RF}}`, `{{CL_KPP_RF}}`, `{{CL_BANK_NAME}}`, `{{CL_BANK_ACCOUNT}}`, `{{CL_BANK_BIK}}`

### Свои переменные
Любой ключ из реквизитов оператора доступен как `{{OP_КЛЮЧ}}`.
Через меню **📄 Шаблоны → 🧩 Свои переменные** можно завести переменную
(например, `contract_number`) — в шаблоне она станет `{{CL_CONTRACT_NUMBER}}`,
а бот будет спрашивать её значение при добавлении каждой новой компании.

## Обновление шаблонов

Через бота (рекомендуется): **📄 Шаблоны** → выбрать тип → «⬆️ Загрузить новый .docx».
Бот проверит файл, покажет найденные плейсхолдеры, подсветит неизвестные и сохранит
резервную копию старого шаблона в `templates/backups/`. Перезапуск не нужен.

Вручную: отредактировать `.docx` в `templates/` — изменения подхватываются сразу.

---

## Отчёт ФН

Меню **📊 Отчёт ФН** → выбрать месяц → указать курс RUB→KGS (запоминается).
Бот пришлёт XLSX с листами «Продажа» (Приложение 4/о) и «Покупка» (Приложение 5/о):
одна строка на транзакцию, суммы в рублях и сомах, строка «Итого».
В отчёт попадают все акты из журнала (счета-заявки не включаются).

---

## Подписанные акты

- После генерации акта или из карточки сделки (🗂 Сделки) — «📎 Прикрепить подписанный».
- Файлы хранятся в Telegram (в БД — только file_id), место на сервере не расходуется.
- **🗂 Сделки → 📦 Архив подписанных** — бот соберёт все подписанные документы клиента в ZIP.

## Деплой на Timeweb VPS (без Docker)

```bash
# Локально или на сервере (нужен Go 1.26+)
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o hodler-bot ./cmd/hodler-bot

mkdir -p /opt/hodler-doc-bot && cp hodler-bot /opt/hodler-doc-bot/
# templates/ и .env положить рядом; data/hodler.db от Python-версии оставить на месте
sudo nano /etc/systemd/system/hodler-bot.service
```

```ini
[Unit]
Description=Hodler Doc Generator Bot
After=network.target

[Service]
WorkingDirectory=/opt/hodler-doc-bot
ExecStart=/opt/hodler-doc-bot/hodler-bot
Restart=always
RestartSec=5
EnvironmentFile=/opt/hodler-doc-bot/.env

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable hodler-bot
sudo systemctl restart hodler-bot
sudo journalctl -u hodler-bot -f
```
